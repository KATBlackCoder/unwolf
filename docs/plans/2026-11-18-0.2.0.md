# Plan — unwolf 0.2.0 : bibliothèque stable pour les applications (2026-11-18, Claude) — VALIDÉ par l'utilisateur le 2026-11-18 (U-D1 à U-D9 telles que recommandées)

**Objectif.** unwolf reste un projet indépendant (dépôt, versions, tests, publication). Hoshi2Star l'utilise
comme une crate ordinaire depuis crates.io (plan UWF de Hoshi2Star, décision UWF-D11). La 0.2.0 regroupe en une
seule fois les changements incompatibles nécessaires, pour que les évolutions suivantes soient de simples ajouts
(0.2.x) et qu'une application n'ait qu'à monter de version.

**État vérifié (lecture seule, `main` @ `dc663b5` = tag `v0.1.2`, publié sur crates.io avec 0.1.0 et 0.1.1).**
Chemins relatifs à `crates/unwolf/src/`.
- Enums publics sans `#[non_exhaustive]` : `Error` (`error.rs:5`), `Event` (`game.rs:66`), `Outcome` (`:99`),
  `PackOutcome` (`:509`), `ProVersion` (`protkey.rs:13`), `ProtectionKey` (`:21`), `FileStatus`
  (`unprotect.rs:25`), et d'autres dans `crypto`, `dxa`. Seul `FileProgress` l'a (`game.rs:114`). Ajouter une
  variante casse donc toute application qui fait un `match` dessus.
- Structures de résultat publiques à champs publics, sans `#[non_exhaustive]` : `GameInfo` (`game.rs:141`),
  `Unprotected` (`:518`), `WolfxReport` (`:526`), `ExtractStats` (`dxa/extract.rs:22`), `PackStats`,
  `FileReport` (`unprotect.rs:33`), `FileResult` (`wolfx.rs:372`). `Options` (`game.rs:48`) est construite
  par les utilisateurs (`Options { config_path, ..Options::default() }`, `lib.rs`).
- Protection Pro : `detect_version` (`protkey.rs:50-56`) rend `V1` pour tout `Game.dat` sans en-tête Pro, y
  compris un `Game.dat` déjà déprotégé (`00 57 …`). Conséquence : `protection_key()` sur un jeu déjà traité par
  `-u` part en V1 et échoue ou rend une clé fausse ; une application ne peut pas savoir « déjà déprotégé ».
  Constaté sur とのかじ 体験版 (Pro 3.7) le 2026-11-18 : avant `-u`, `Game.dat` = `57 50 … 57` ; après, `00 57 …`.
- `Session` n'est pas `Send` : rappel `Box<dyn FnMut(&Event)>` (`game.rs:158-162`). Une application asynchrone
  doit la créer et l'utiliser dans un seul fil.
- Surface publique large : `crypto`, `rng`, `wolfrpg`, `wolfx`, `fsutil`, `pro`, `protkey`… sont `pub`
  (`lib.rs`). Tout élément public est figé par la compatibilité. Usages hors bibliothèque : `config`, `dxa`,
  `fsutil`, `game`, `modes`, `unprotect` (commande `main.rs`, `tests/`, `examples/`).
- Pas de CI (`.github/` : `FUNDING.yml`, modèle d'issue), pas de `CHANGELOG.md`.
- Édition 2024, `rust-version = "1.85"`.

## Décisions (recommandation en gras)

- **U-D1 — Version.** **0.2.0** (changements incompatibles regroupés). Pas de 1.0 tant que l'API n'a pas servi
  dans Hoshi2Star.
- **U-D2 — Enums et résultats extensibles.** **`#[non_exhaustive]`** sur tous les enums publics de l'API
  (`Error`, `Event`, `Outcome`, `PackOutcome`, `ProVersion`, `ProtectionKey`, `FileStatus`, et le nouvel état de
  protection) et sur les structures de résultat (`GameInfo`, `Unprotected`, `WolfxReport`, `ExtractStats`,
  `PackStats`, `FileReport`, `FileResult`). La commande (`main.rs`) est une crate à part : ses `match` sur ces
  enums (`print_event`, `FileStatus`, `Outcome`) gagnent un bras `_`.
- **U-D3 — `Options`.** **`#[non_exhaustive]` + constructeur** `Options::new(config_path)` et méthode
  `overwrite(bool)` (une structure `#[non_exhaustive]` ne peut plus être écrite littéralement hors de la crate) ;
  exemple de `lib.rs` et README mis à jour. Ajouter une option plus tard ne cassera plus rien.
- **U-D4 — État de protection.** Nouveau `enum ProtectionStatus { NotPro, Unprotected, Protected(ProVersion) }`
  et `Session::protection_status()` : pas de fichier clé Pro ⇒ `NotPro` ; `BasicData` extrait au besoin (comme
  `protection_key`) ; `Game.dat` sans en-tête Pro ⇒ `Unprotected` ; sinon `Protected(detect_version)`.
  `protection_key()` rend `Ok(None)` aussi pour un jeu `Unprotected` (au lieu d'échouer en V1), et `-u` sur un
  jeu déjà déprotégé affiche « already unprotected » au lieu d'une erreur.
- **U-D5 — `Session` `Send`.** **Rappel `Box<dyn FnMut(&Event) + Send>`**, et test statique que `Session` est
  `Send` (`fn assert_send<T: Send>() {}`). Rupture pour un rappel qui capture un `Rc` : acceptable en 0.2.
- **U-D6 — Surface publique.** **Réduire** : garder publics `game`, `dxa` (`Archive`, `extract_to`,
  `pack_directory`, `Source`, `Cipher`), `modes`, `config`, `protkey` (types), `unprotect` (types), `Error`,
  `Result` ; passer les autres modules en `pub(crate)` ou, si un test, un exemple ou un script en a besoin,
  `#[doc(hidden)] pub` avec la mention « hors API stable ». À trancher : `wolfx`, `wolfrpg` (utiles à d'autres
  outils ?).
- **U-D7 — CI.** GitHub Actions sur push et PR : `cargo fmt --check` ; `cargo clippy --all-targets -- -D
  warnings` avec et sans `--no-default-features` ; `cargo test` (les deux) ; `cargo doc --no-deps` avec
  `RUSTDOCFLAGS=-D warnings` ; une tâche MSRV en Rust 1.85 ; `cargo-semver-checks` contre la dernière version
  publiée (pour la 0.2.0 il signalera les ruptures, attendues). Elle sert de gate : aucune compilation sur le PC
  de l'utilisateur (gel constaté avec Hoshi2Star).
- **U-D8 — `CHANGELOG.md`.** Format « Keep a Changelog », en anglais comme le README ; 0.1.0 à 0.1.2 reconstruits
  depuis `git log`, puis 0.2.0 avec une section « Migration from 0.1 ».
- **U-D9 — Git et publication.** Branche `release/0.2.0`, une PR ; commits avec l'adresse noreply
  (`95929939+KATBlackCoder@users.noreply.github.com` : la config locale de ce dépôt porte encore l'adresse
  Gmail, que GitHub refuse) ; l'utilisateur fusionne, crée le tag `v0.2.0` et lance `cargo publish`.
